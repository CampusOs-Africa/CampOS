# CampusOS — Backend Architecture, Quai EVM & Blip Pay Integration (Milestones 2–5)

This backend implements **Milestone 2 (Verified Identity)**, **Milestone 3 (Quai EVM Integration)**, **Milestone 4 (Quai Campus Wallet)**, and **Milestone 5 (Trusted Campus Marketplace, Blip Pay Checkout & Quai Escrow)** for **CampusOS**, the trusted digital operating system for African universities built for the **Quai × Blip Buildathon**.

---

## 1. Milestone 5: Complete Marketplace, Escrow & Blip Pay Backend

The Milestone 5 backend is built on **SQLAlchemy 2.0**, **Pydantic v2**, and the **Repository Pattern** within our **Modular Monolith Architecture**. It provides a 100% scam-free campus commerce engine where sellers are gated by Verified Student Identity, payments are processed by Blip Pay, and funds are locked in Quai Network smart contract escrow (`MarketplaceEscrow.sol`).

### Core Models (`app/models/`)
* **`MarketplaceListing` & `MarketplaceCategory` (`app/models/marketplace.py`):**
  * Implements `id` (UUIDv4 PK), `seller_id` (FK to `users.id`, cascade delete), `title`, `description`, `category` (`books`, `electronics`, `accommodation`, `tutoring`, `tickets`, `services`), `price`, `condition` (`new`, `like_new`, `good`, `fair`, `poor`), `images` (JSON ARRAY of Cloudinary URLs), `status` (`active`, `pending_order`, `sold`, `suspended`), `inventory_count`, and UTC timestamps.
  * Includes `MarketplaceCategory` with default seeded campus categories and active listing counts.
* **`Order`, `OrderItem` & `PaymentRecord` (`app/models/order.py`):**
  * Implements multi-item support (`OrderItem`) and order lifecycle tracking (`initiated`, `escrow_locked`, `delivered_pending_release`, `completed`, `refunded`, `disputed`, `cancelled`).
  * Explicit audit logging in `PaymentRecord` (`blip_payment_records`) tracking amount, currency, provider (`blip_pay`), and raw webhook payloads.
* **`EscrowRecord` (`app/models/escrow.py`):**
  * Tracks Quai Network escrow state (`CREATED`, `FUNDED`, `COMPLETED`, `REFUNDED`, `CANCELLED`, `DISPUTED`), Quai order ID (`0xquai_escrow_...`), transaction receipt hash (`escrow_tx_hash`), and timeout expiration timestamp (`expires_at`).
* **`Review` (`app/models/review.py`):**
  * Tracks 1–5 star ratings and comments on completed escrow orders.

## 3. Repositories & Services (`app/repositories/` & `app/services/`)
* **Repositories:**
  * `MarketplaceRepository`: Filterable catalog queries (category, condition, min/max price, keyword search across title/description, pagination), seller profile lookups, and category CRUD.
  * `OrderRepository`: Multi-item order CRUD, payment reference lookup, buyer/seller paginated history, and payment record audit logging.
  * `EscrowRepository`: EscrowRecord CRUD, order ID mapping, Quai order reference lookup, and state transitions.
  * `PaymentRepository`: PaymentRecord CRUD and order/user payment history.
* **Services:**
  * `MarketplaceService`: Gated by Verified Student Identity (`verification_status == 'verified'`). Uploads images via Cloudinary (`StorageService`), lists categories, and builds composite seller reputation profiles.
  * `PaymentService`: Inventory row-level locking (`with_for_update()`), checkout initiation, duplicate payment protection, and constant-time HMAC-SHA256 signature verification (`hmac.compare_digest`).
  * `OrderService`: Webhook idempotency (`if order.status != 'initiated': return order`), inventory decrementing, order cancellation, delivery confirmation, Quai smart contract escrow release (`quai_blockchain_service.storeCredentialHash`), and automatic **+5 Trust Score to Buyer and Seller**.
  * `EscrowService`: Orchestrates `EscrowRecord` lifecycle (`create`, `release`, `refund`, `dispute`, `get`).
  * `TrustService`: Deterministic, bounded 0–100 Trust Score engine rules (+10 Verified Student, +5 Buy, +5 Sell, +2 Review, -5 Refund, -10 Fraud).
